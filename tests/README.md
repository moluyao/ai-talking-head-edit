# rough_cut.py 测试说明

`rough_cut.py` 是整理者补充的实验性脚本，不是原视频内容。
下面如实记录它测过什么、没测过什么。

## 1. 自动测试（任何人都能复现，不需要素材）

```bash
python tests/test_rough_cut.py          # 通过后自动删除临时文件；加 --keep 保留
```

测试素材：
- 生成一段「类语音」调制噪声，按已知长度插入 9 个停顿（0.2–2.0s）；
- 加 -60dB 底噪，配 30fps 测试画面。

检查项：
1. 源停顿测量误差 ≤0.05s；
2. 剪完后，成片停顿压到规则值，误差 ≤0.05s；
3. 开口前留 0.15s、说完后留 0.2s；音画时长一致；
4. `drops` 按 speech 的精确起止删掉一整句后：有声段少一个，拼接处停顿按规则重算，不会出现两段停顿叠加；
5. 音轨起始时间不为 0（模拟手机素材，音轨延后 0.4s）时，测量时间整体正确后移，剪完的停顿依然正确；
6. 带封面图的 m4a 不会被当成视频，能输出 mp3。

结果（2026-11-17，ffmpeg 9.0 / Python 3.12 / Windows 11）：**全部通过**。

| 源停顿 | 0.20 | 0.30 | 0.50 | 0.70 | 1.00 | 1.20 | 2.00 | 0.60 | 1.40 |
|---|---|---|---|---|---|---|---|---|---|
| 规则期望 | 0.20 | 0.30 | 0.40 | 0.40 | 0.55 | 0.55 | 0.70 | 0.40 | 0.55 |
| 成片实测 | 0.20 | 0.28 | 0.38 | 0.39 | 0.54 | 0.55 | 0.72 | 0.38 | 0.56 |

其它结果：
- 删除一整句后，拼接处停顿 0.39s（期望 0.40）；
- 音轨延后 0.4s 时，测得起点后移 0.400s；
- 音画时长差 0.000s。

## 2. 真实中文语音测试（整理者本地跑过，未随仓库附带音频）

测试素材：
- 用 TTS 生成 10 句中文口播，其中一句是「说一半重来」的半句；
- 句间插入已知长度的停顿（0.25–2.2s）；
- 加 -55dB 粉红底噪和 50Hz 电流声。

| 检查项 | 结果 |
|---|---|
| 9 处插入停顿的边界定位 | 起点、终点误差 ≤0.05s，多数 ≤0.01s |
| 成片停顿符合规则 | 9/9 通过（误差 ≤0.02s） |
| 句内逗号等自然停顿 | 0.16–0.42s，被正确保留或只轻度压缩 |
| 剪切后有没有切掉字 | faster-whisper 转写前后对比，文字一致（仅标点差异） |
| `drops` 删除「说一半重来」的半句 | 只删掉了半句，前后文字完整 |

## 3. 独立审查

发布前另请了两个独立 agent，一个只看代码找 bug，一个扮演新用户只读文档从零跑通。
它们发现、现已修复的问题：
- 音轨起始时间不为 0 时，所有切点整体错位（手机素材常见）；
- 删掉一段后，拼接处的两段停顿叠加，变成约 1.1s；
- 带封面图的音频被当成视频，输出 mp3 失败；
- 素材没有音轨、或 drops 删光全部内容时，只给出看不懂的报错；
- 输出 .mp3 / .wav 时编码器不对；
- ffmpeg 版本兼容的回退逻辑会被别的错误误触发；
- 可变帧率（VFR）素材被强行对齐到帧网格；
- Windows 控制台中文乱码；
- pauses.json 里存了本机绝对路径；
- 交付说明把已删除的停顿也列成「被压缩」。

开发过程中自测发现并修复的问题：
- 阈值原用分位数法，长停顿一多阈值就漂移。已改为 Otsu 自适应阈值。
- 句尾轻声被切掉。已加双阈值向外延伸。
- 起音里单帧电平凹陷会截断边界。已改成连续 3 帧低于低阈值才算到头。
- ffmpeg 7 以上版本去掉了 `-filter_complex_script`。已自动兼容新旧版本。

## 4. 没测过的（请注意）

- **没有用真人录制的原始口播测过**：真人录音的口癖、吸气声、环境噪声都比 TTS 复杂。
- 背景音乐很响的素材：不适用。原视频里带配乐的片段测试失败，这是设计上就不支持的。
- 只在 Windows 上跑过，macOS 和 Linux 未验证。
- 长素材切点上千处时渲染慢，未做性能测试。
- 剪映工程导出、挑 Take、跨 Take 拼接不在脚本范围内。

欢迎用真实口播原片测试后提 Issue，附上 `pauses.json` 和交付说明即可（json 里只存文件名，不含本机路径）。
