# AI 口播剪辑工作流（SOP）

> **原创声明**：本工作流及其中的「剪气口 / 挑 Take」提示词原创自 **大师的AI小灶**（X [@dashiAIxz](https://x.com/dashiAIxz)，GitHub [chuspeeism](https://github.com/chuspeeism)），出自其视频[《全网最深度的 AI 剪辑教程》](https://x.com/dashiAIxz/status/2122492466490433678)（2026-11-17）。本文件是学习笔记式整理，版权归原作者；如原作者要求删除，我们会立即处理。

原作者团队用这套流程剪了约 10 条视频，单条从人工一周压到 2–3 天；照做的话，**2 小时内能出一版可看的片子**。下面是提炼后的可执行版本；标「替代方案」的地方是整理者补充的，不是原视频内容。

总流程：**素材准备 → 视频生成 → 反馈优化 → 最终交付**

---

## 0. 开工前必须有两样东西

### 0.1 脚本表（最重要）
一张表，每行对应一段口播。没有「画面要求」列，Claude 就会按自己的理解乱排分镜。

| 列 | 写什么 | 例子 |
|---|---|---|
| 口播字幕 | 这一段要说的话，一字不差 | 上期 30 万人看过…… |
| 画面描述 | 这一段画面的具体要求和说明 | 画面收缩到 Claude 对话框中，录屏或截图 |
| 花字 | 需要在画面上强调的文字 | "口播调色" |
| 分镜参考 | 想要的效果，贴图或视频 | 一张喜欢的分镜截图 |
| 后期资料提供 | 这一段要用到的素材 | 文档链接、案例视频、图片 |

原教程用飞书文档 + 飞书 CLI 让 Claude 读取。替代方案：没有飞书就用本地 `脚本.md`（Markdown 表格）+ 素材文件夹，路径写进提示词即可。

### 0.2 口播素材（三选一）
1. **真人自己录**（推荐）——观众喜好和平台算法上都更自然。
2. **社恐 / 镜头感差** → 数字人：Seedance 2.5、可灵。
3. **完全不露脸** → 声音模型配旁白：Gemini 3.8 Flash TTS、阿里 CosyVoice 3。画面全部用动画分镜生成。

数字人首帧照片三条硬规则（照片会被当作生成的第一帧）：
- 不要摆拍感过重的照片；
- **手不要出现在画面里**，否则很长一段时间双手都会留在画面中；
- **照片要露出牙齿**，否则模型会自己"生成"牙齿，观感很差。

AI 配音（尤其是用自己声纹克隆的）：**不要加太多语气提示词**，加多了会出怪腔。

## 1. 视频生成（一条主提示词搞定）

### 1.1 调色：给参考图，别让模型自己调
模型对中国人肤色的美颜 / 调色学得不好，直接让它调效果很差。
做法：自己先调好**一张**截图（剪映 / 醒图 / LR 都行），作为附件给 Claude：「人物画面调色对照附件图片的色调，把全片复刻成同样效果」。调色和粗剪共用同一张参数表。

### 1.2 分镜：用动画风格 skill
原作者用自家开源 skill [`dashi-animationstyle`](https://github.com/chuspeeism/dashi-animationstyle)（HTML/Canvas 写动画，无头 Chrome 逐帧截图合成，视频口述「8 种精选分镜风格」，README 写「自带 7 套风格」：立体卡通、黑底科技、复古剪纸、复古报刊、扁平流程图、手绘笔记等）。
替代方案：任何「HTML/Canvas 或 GSAP 写动画 → 无头浏览器逐帧截图 → ffmpeg 合成」的管线都可以。

### 1.3 BGM：给它，或让它自己去网站下
Claude 自带的配乐能力很基础（只能出电子音那一类）。两种做法：
- 直接给一首 BGM 附件。长度不对没关系，Claude 能自己剪成与成片等长、无接缝的版本；
- 更自动：浏览器里先登录好音乐网站会员，让 Claude 用浏览器控制（如 Claude in Chrome 等浏览器扩展）搜和主题相关的 BGM 下载。
- ⚠️ 版权：会员下载的曲子是否允许用在发布的视频里，要看该网站的授权条款，发布前确认。

### 1.4 音效：Openverse
「音效通过 Openverse 项目匹配合适的音效」——能明显提升音效质量。Openverse 上是 CC 授权素材，商用前检查具体协议（CC0 / CC BY 需署名 / NC 不可商用）。

### 1.5 主提示词模板
```
帮我制作一个视频，脚本与相关资源在 <脚本.md 路径 / 飞书链接>。
画面上，根据文档中的内容，通过 <动画分镜 skill> 帮我制作视频。
人物画面调色对照附件图片中的色调来调整。
配音上，BGM 使用附件中我给你的音乐
  （或：通过浏览器控制，在我电脑浏览器上已登录的 <音乐网站> 里寻找合适的 BGM）。
音效通过 Openverse 项目来匹配合适的音效。
```
模型：原作者用 Opus 5.5、**推理强度 Medium 即可**，调高没有明显收益。

### 1.6 关键技巧：先只做开头 30 秒
在主提示词后追加：
```
先只帮我制作视频开头 30 秒的部分。开头最关键的是视觉效果和叙事趣味性，
所以要尽量把每个视觉细节都打磨好，动画效果一定要有吸引力、效果细腻。
```
- 一次任务把算力集中在开头，注意力更集中，减少后期返工；
- 开头是平台算法最看重的指标（原作者用小号验证过，精良开头和普通开头数据差距非常大）；
- 开头细节调好后，再让它延展成全片。

## 2. 粗剪：剪气口 / 挑 Take 提示词（原样可用）

AI 理解不到位最典型的就是气口。原作者摸索一个多月后的提示词（视频 9:22 截取全文）。注意：最后一行【交付】在视频里被字幕挡住，只能看清开头「附上每段使用的 Take 及……」，后半句是整理者推断补的，不是原文。「60帧」原文如此，大概率指 60fps。

```
【流程】先出只有人物口播的粗剪视频（60帧），确认后再导剪映工程。工程使用整条素材加入出点引用，片段可拖回；调色与粗剪共用同一张参数表。
【依据】以脚本为准判断漏说、多说和重复；脚本里本来就重复的内容不算重复。脚本有但没录的句子列入交付说明。
【留白与停顿】开口和说完按实测的有声起音、收音计算，不按转写时间。
开口前留0.15秒，说完后留0.2秒。
0.35秒以内的自然停顿保留。
超过0.35秒的停顿：句内犹豫缩到约0.4秒；逗号0.35~0.45秒；句号0.55秒；换段0.7秒。
剪掉口癖后的句内拼接处只留0.04秒。
切点保留尾音余韵，但吸气、咳嗽等杂音不因此保留；句间呼吸静音在整片环节处理，不改变节奏。
【重复与重说】同一段内容录了两遍及以上时只留一遍，其余从时间线剔除。说一半重来的半截也要剔除，只留说完整的那次。句内超过0.35秒的停顿前后要单独转写，且不带提示词，防止重说被转写吞掉。
【挑Take】按整句块比较，不按短停顿切开比较。
准确且画面可用：无口误、卡壳、吞音、颠倒词序；人物景别和位置一致；开口时已坐稳，说完前没有起身。
语调饱满、重音准确、情绪有感染力。差距不明显时列出候选，由人工选择。
前后气口连贯。
条件相同时，优先选能整段使用的一遍；仍分不出时用后录的一遍。
【跨Take拼接】整段能用同一遍就不拼。确实需要拼接时：
只在实测有静音的逗号、句号处拼接，不在词中间或气流未断处切。
切点留白按【留白与停顿】执行。
人物姿势或位置差异明显时不拼。
每处拼接都列入交付说明。
【衔接】口播片段之间一律硬切。
【声音】音频只做剪辑必需的操作，不额外加压缩、EQ、降噪或去混响。
【无法解决的瑕疵】所有版本都有瑕疵且拼接无法解决，或只录了一遍且有瑕疵时，时间线放瑕疵最轻的一遍。脚本有但没录的句子，在对应位置标明。粗剪交付说明列出时间码和问题。
【交付】附上每段使用的 Take 及（以下为推断）拼接位置、各项问题的时间码清单。
```

### 2.1 辅助脚本 `scripts/rough_cut.py`（整理者补充，实验性，非原视频内容）

把上面【留白与停顿】那一节做成可执行的工具。脚本只负责测量和机械剪切；
哪段是重复或重说、每个停顿该算逗号还是句号，仍然由 Claude 对照转写来判断。

依赖：Python 3.9+、`numpy`、`ffmpeg` / `ffprobe`（需在 PATH 中，推荐 5.1 以上）。
下面的 `scripts/` 是相对本 skill 目录的路径；装到 `~/.claude/skills/` 后，完整路径是 `~/.claude/skills/ai-talking-head-edit/scripts/rough_cut.py`。

```bash
python scripts/rough_cut.py analyze 口播.mp4 -o pauses.json
# Claude 读转写，修改 pauses.json：
#   pauses[].label 改成真实标点：keep / hesitation / comma / period / paragraph / splice
#   drops 里填要删掉的源时间区间：[[开始秒, 结束秒, "原因"], ...]，用于重复、说一半重来、口癖
#     删整句：直接填 speech[] 里那段的起止时间即可，拼接处停顿会自动按「保留那句之后的停顿标签」重算
#     删句内口癖：填口癖本身的时间，拼接处自动只留 0.04s（splice）
python scripts/rough_cut.py cut 口播.mp4 pauses.json -o 粗剪.mp4   # 同时生成 粗剪_交付说明.md
```

- 有声边界按实测音频能量判定（Otsu 自适应阈值 + 双阈值延伸），不依赖语音识别的时间戳。
- 默认标签只按停顿时长猜，**一定要让 Claude 对照转写改过再 cut**。
- 同一批素材想保持一致，可以用 `--threshold-db` 锁定阈值。
- 已知局限：
  - 吸气、咳嗽的响度接近人声时，会被当成有声段保留；
  - 背景音乐很响的素材不适用（只为干净的口播原片设计）；
  - 挑 Take、跨 Take 拼接不在脚本范围内；
  - 脚本不改帧率，提示词里「60帧」的粗剪需要另行转换；
  - 长素材切点很多（上千处）时渲染会比较慢。
- 支持：音轨起始时间不为 0 的手机/相机素材、可变帧率素材、带封面的音频文件；输出扩展名用 `.mp3/.wav/.m4a/.flac` 时只输出音频。
- 测试方法和结果见仓库的 `tests/README.md`。

实现提示（整理者补充）：起音/收音「实测」= 用音频能量（RMS / ffmpeg silencedetect）找真实有声边界，不用语音识别的时间戳。

### 2.2 其它文件

- `prompts/`：主提示词、先做开头 30 秒、剪气口粗剪、轮询剪辑意见，共四份，原文出自原视频，可直接复制。

## 3. 反馈优化（收尾环节，2–3 轮）

### 3.1 用表格提意见
建一份「剪辑意见」文档（飞书文档，或本地 `剪辑意见.md`），一行一条：

| 截图 | 时间码 | 意见 | 标签 |
|---|---|---|---|
| (截图) | 03:24 | 字幕重复 | 局部 / **全局** |

- 时间码 + 截图让 AI 精准定位，**不用从头看整条视频，省大量 token**；
- 普遍性问题打「全局」标签；
- 可反馈：节奏、信息表达、气口、敏感信息打码等——这些 AI 都能直接理解。

### 3.2 人和 AI 并行
Claude 改 + 渲染动辄几小时，干等很浪费。告诉它：
```
每 10 分钟检查一次 <剪辑意见文档> 的更新，有新意见就继续改，直到全部改完。
```
（Claude Code 里可用 `/loop 10m` 实现。）文档还能分享给同事一起提意见，不需要每人都装 Claude。

### 3.3 AI 搞不定的部分 → 导剪映工程人工补
玩梗、表情包、幽默感这类"跟人性挂钩"的东西，反复提意见 AI 也很难理解。此时要求它**导出剪映工程文件**：分段视频、字幕、配音都分轨整理好，人工改起来很方便。
实现提示：剪映草稿是 `draft_content.json` 这类私有格式，版本间会变；可借助开源库 pyJianYingDraft 生成，导出后先在剪映里打开验证。做不到时退而交付分轨素材（每段视频 + SRT 字幕 + 配音 / BGM 分轨）。

## 4. 全自动模式（不露脸）

脚本 → AI 配音（自己的声纹）→ 动画分镜 → 剪辑 → 甚至发布，全部在一个 Claude 会话里完成。原作者这样做的科普视频最高 1600 赞。适合量产，但上限低于真人口播版。

---

## 5. 核心原则
- 准备阶段（脚本表 + 口播）的质量决定上限；画面要求不写，AI 就自由发挥。
- 能给参考就别让它猜：调色给图、BGM 给曲、分镜给 skill。
- 集中算力先做开头，再铺全片。
- 反馈结构化（时间码 + 截图 + 标签），并让 AI 轮询意见文档。
- 创作者的关键能力：**分清哪些放心交给 AI，哪些必须自己做**（梗、幽默、最终审美）。
